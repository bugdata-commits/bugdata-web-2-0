# BugData Web 2.0 Delivery Checklist

## Premium homepage experience

- [ ] The separate BugData Web 2.0 prototype presents a world-class, mobile-first homepage without modifying the current live-site repository.
- [ ] The hero communicates practical growth infrastructure for Zimbabwean businesses across AI automation, local SEO, hosting and reliability, and digital growth.
- [ ] The homepage provides a primary `Book an assessment` action and a secondary `See how we help` action.
- [ ] The homepage includes original BugData signal-board visual language, not copied protected layouts, wording, branding, screenshots, or animations from reference websites.

## Navigation and conversion

- [ ] The header includes Services, Approach, Results, Insights, Contact, a separate Client portal route, and a primary assessment action.
- [ ] The mobile navigation is keyboard-accessible, uses large touch targets, and keeps the booking action visible.
- [ ] The page includes a WhatsApp-first assessment handoff, phone/email alternatives, and a short form without inventing backend submission behavior.
- [ ] The page includes a `Choose your goal` path for getting found locally, automating work, improving reliability, and growing demand.

## Offer clarity and proof

- [ ] The page includes four service pathways: AI Automation, Local SEO, Hosting & Reliability, and Digital Growth.
- [ ] The page shows a Diagnose → Build → Launch → Improve process with operational annotations.
- [ ] The page includes transparent proof/measurement language and does not publish invented client logos, rankings, leads, revenue, uptime, ROI, or performance statistics.
- [ ] The page includes three scoped package concepts: Visibility, Automation, and Growth Operations.
- [ ] The page includes technical reassurance for backups, security, support, integrations, and low-bandwidth delivery.

## Accessibility, SEO, and delivery

- [ ] Initial HTML contains meaningful content, route-specific metadata, canonical/social metadata, and semantic headings.
- [ ] `manus-routes.json` is served successfully and reflects all public prototype routes.
- [ ] `sitemap.xml`, `robots.txt`, and the web manifest are present and consistent with the prototype routes.
- [ ] Reduced-motion, visible focus, semantic controls, labels, and keyboard interaction states are implemented.
- [ ] Desktop and mobile preview layouts are checked before delivery.
- [ ] The prototype is committed to a separate private GitHub repository named `bugdata-web-2-0` through the managed canonical GitHub flow.
